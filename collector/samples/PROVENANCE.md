# Sample provenance

The samples here are real sensor output, not hand-written fixtures. They were
captured from the repository's own PCAPs in `tests/captures/` so the collector's
field mappings and the collector-to-rule proof are reproducible.

## Suricata

The stock Suricata configuration restricts `eve-log` types and disables the
Modbus/DNP3 application layers, so both are enabled explicitly; the Modbus and
DNP3 eve types are appended after the 34 types the image ships.

```bash
C=tests/captures
for name in modbus_attack modbus_benign dnp3_attack dnp3_benign; do
  mkdir -p /tmp/collector/$name
  docker run --rm -v "$C":/pcap:ro -v /tmp/collector:/out jasonish/suricata:latest \
    -r /pcap/$name.pcap \
    --set app-layer.protocols.modbus.enabled=yes \
    --set app-layer.protocols.dnp3.enabled=yes \
    --set outputs.1.eve-log.types.34=modbus \
    --set outputs.1.eve-log.types.35=dnp3 \
    -l /out/$name
done
```

Each `*.eve.json` here is the `modbus`/`dnp3` records from the run, with
`flow`/`stats`/`anomaly` records dropped.

## Zeek

```bash
C=tests/captures
for name in modbus_attack modbus_benign dnp3_attack dnp3_benign; do
  mkdir -p /tmp/zeek/$name
  docker run --rm -v "$C":/pcap:ro -v /tmp/zeek/$name:/out -w /out \
    zeek/zeek zeek -r /pcap/$name.pcap
done
```

The `*.modbus.log` / `*.dnp3.log` files are copied verbatim (headers included).
Zeek only writes a protocol log when it sees that protocol, which is why each
sample carries one protocol rather than both.

Both images ran as containers; the captures themselves were generated by
`tools/make_captures.py`.

# Functional validation report

The native rules are not just structurally linted; they are run through Suricata
against committed captures. This report records the result. Regenerate with:

```bash
make suricata-check
```

| Field | Value |
| :--- | :--- |
| Suricata | 8.0.6 RELEASE (container `jasonish/suricata:latest`) |
| Ruleset | `deploy/suricata/ot-detection.rules` |
| Captures | `tests/captures/*.pcap`, generated by `tools/make_captures.py` |
| Evidence | `deploy/evidence/<capture>/eve.json` (alert records only) |

Every attack capture fires exactly the expected signatures and every benign
capture is silent.

## What the run found

- **Modbus and DNP3 application-layer detection is disabled by default.** The
  stock Suricata configuration ships `app-layer.protocols.{modbus,dnp3}.enabled:
  no`, so the ruleset fails to load until both are enabled. The runner sets them
  with `--set`; any deployment must enable them in `suricata.yaml`.
- **The original exception-burst rule was invalid.** `modbus: function > 128`
  is not valid Suricata syntax, and the legacy `modbus` keyword matches requests
  only, so exception responses cannot be inspected with it. The rule was
  replaced with a request-side detection of writes above any plausible register
  map (sid 1000004), which fires on the capture.
- **OPC UA rules fire on the message header alone.** Suricata has no OPC UA
  application-layer parser, so those rules match the 3-byte message type with
  `content`/`depth`. Application-layer OPC UA detection would need a decoder,
  as with DNP3.

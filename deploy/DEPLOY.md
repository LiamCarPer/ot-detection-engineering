# Deployment runbook

Everything under `deploy/` is generated from the single rule source by
`pipelines/deploy.py` and committed so it can be installed directly. Do not edit
these files by hand; edit the rule and re-run:

```bash
python pipelines/deploy.py           # regenerate
python pipelines/deploy.py --check   # CI drift check
```

`deploy/manifest.json` links every artifact to the rule revision that produced it
(source path and SHA-256). The log fields the Sigma-derived rules expect are in
[docs/TELEMETRY.md](../docs/TELEMETRY.md).

| Directory | Target |
| :--- | :--- |
| `deploy/loki/rules/` | Grafana Loki ruler alert rules (LogQL) |
| `deploy/suricata/ot-detection.rules` | Suricata ruleset (Modbus, DNP3, OPC UA, S7comm) |
| `deploy/splunk/` | Splunk saved searches (SPL) |
| `deploy/sentinel/` | Microsoft Sentinel analytics queries (KQL) |
| `deploy/opensearch/` | OpenSearch PPL queries |
| `deploy/evidence/` | Functional-validation evidence: Suricata, Loki ruler, Malcolm, live lab, decoder, collector, behaviour-baseline and conduit runs (not generated by the pipeline) |

`manifest.json` records every artifact, and marks a rule `unsupported` for a
target it cannot be converted to. The correlation rule converts for Loki, Splunk
and OpenSearch but not Sentinel — the Kusto backend does not implement the
correlation type — so it has no `deploy/sentinel/` artifact.

## Loki

Loki evaluates alerting rules with the ruler. Point the ruler at this directory
and enable it in `loki-config.yaml`:

```yaml
ruler:
  storage:
    type: local
    local:
      directory: /etc/loki/rules
  rule_path: /tmp/loki/rules
  alertmanager_url: http://alertmanager:9093
  ring:
    kvstore:
      store: inmemory
  enable_api: true
```

Local ruler storage is tenant-scoped: mount the rule files under
`<rules-dir>/<tenant>/` (with `auth_enabled: false` the tenant is `fake`), then
reload. Each rule file contains one group named after its rule. The queries use
the `logfmt` parser, so the Modbus, DNP3, S7comm, firewall and process events
must be shipped with the fields defined in docs/TELEMETRY.md. Application-layer
DNP3 and S7comm events are produced by [tools/dnp3-dpi](../tools/dnp3-dpi) and
[tools/s7comm-dpi](../tools/s7comm-dpi).

Each query also selects its stream by the `service` label — for example
`{job=~".+", service="modbus"}` — so a rule can only match the protocol it was
written for. Ship every normalized stream with the `service` label from
docs/TELEMETRY.md (`modbus`, `dnp3`, `s7comm`, `opcua`, `iptables`,
`safety_monitor`); a stream without it will not match any rule. The logsource to
selector mapping is applied by `pipelines/loki_pipeline.py` at conversion time.

A correlation rule is a metric query, not an alert-on-a-line rule, and the pinned
Loki backend's ruler output for one is not valid LogQL; the bundle builds the
correlation ruler document from the backend's default-format query instead
(`pipelines/loki_correlation.py`). Correlation rules are also excluded from the
generated policy rules, which are for `rules/sigma` and `rules/native`.

## Suricata

```bash
suricata -T -S deploy/suricata/ot-detection.rules -c /etc/suricata/suricata.yaml
cp deploy/suricata/ot-detection.rules /etc/suricata/rules/ot-detection.rules
suricatasc -c reload-rules
```

The rules cover Modbus (unauthorized writes, device scan, undefined-register
writes), DNP3 (unauthorized control/write, control operations, reporting
suppression, restarts), OPC UA (TCP Hello and OpenSecureChannel from unapproved
clients) and S7comm (program download/upload, PLC control/stop, unauthorized
writes). `Suricata 7+` is required for the DNP3 and Modbus application-layer
keywords; the OPC UA and S7comm rules match on the TCP payload.

## Splunk

Splunk reads a single `savedsearches.conf` per app. Concatenate the generated
files into an app:

```bash
mkdir -p $SPLUNK_HOME/etc/apps/ot_detection/local
cat deploy/splunk/*.conf > $SPLUNK_HOME/etc/apps/ot_detection/local/savedsearches.conf
```

Field names in the SPL are the normalized telemetry fields; map them to your
sourcetype with a field extraction or a `props.conf`/`transforms.conf` pair.

## Microsoft Sentinel

Each `deploy/sentinel/*.kql` file is an analytics rule query. Create a scheduled
analytics rule per file, set the severity from the rule's Sigma `level`, and map
the entity fields (`src_ip`, `dst_ip`, `link_source`, `link_destination`) in the
rule's entity mapping.

## OpenSearch

Each `deploy/opensearch/*.ppl` file is a PPL query. Use it in an alerting monitor
over the index pattern named in the query (for example `ot_ndr-modbus-*`).

## Provenance and drift

```bash
python pipelines/deploy.py --check
```

fails when a committed artifact no longer matches the rule that produced it, so
a rule change without regenerating the bundle is caught in CI.

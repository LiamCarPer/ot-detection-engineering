# Incident 2026-11-25 — unauthorized Modbus write and gateway containment

**Scope:** OT-Security-Lab, not a production plant. One source, one controller,
one containment action. The point is the loop, not a claim of real incident
response.

## Detection

The lab emitted three `UNAUTHORIZED_MODBUS_WRITE` alerts. The repository rule
`ot_modbus_unauthorized_write` is the detection: it fires on an FC6/FC16 write
from a source outside the approved writer list, and the live purple run exercised
it three times; the Modbus-write step’s MTTD is about 2.0 s (non-process mean 2.53 s).

The write targeted register 1 on `172.21.0.10`. The lab's Modbus anomaly detector
and the repository rule agree on the source and the write; the repository rule
does not depend on the lab's alert label.

## Containment

The responder applied:

```bash
iptables -I FORWARD -s 172.24.0.10 -j DROP
```

This is the OT-safe containment: the PLC stays running, the source is isolated at
the gateway, and the action is reversible. No controller restart, no process
shutdown.

## Recovery

```bash
iptables -D FORWARD -s 172.24.0.10 -j DROP
```

The block was removed and the responder returned to dry-run. The lab's normal
background polling resumed.

## Post-incident change

The rule did not need a threshold change: it detected the first write. The
post-incident change is in the operational layer:

- `docs/runbooks/modbus-unauthorized-write.md` now records the responder
  threshold, the verification command and the rollback command.
- The runbook no longer says to rotate "Modbus credentials"; Modbus has no
  authentication, so the action is host credential rotation and EWS/HMI review.
- The incident is the reference scenario for the containment path; adding another
  Sigma rule would be coverage padding, not a lesson from this event.

## What this does not prove

- The lab is a Dockerised plant; there is no physical valve, pump or safety
  instrumented system.
- The responder is a lab control on the gateway, not a plant change-management
  or safety-instrumented action.
- There is no 24/7 SOC, on-call rota or analyst MTTA in this timeline.
- The block stops the source at the gateway; it does not clean the host. Host
  eradication is out of scope for this lab.
